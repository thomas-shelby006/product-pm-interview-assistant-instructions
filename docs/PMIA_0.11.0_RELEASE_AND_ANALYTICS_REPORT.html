Executive summary

0.11.0 turns PMIA from a two-window answer transport into a production-primary interview runtime with an optional comparison agent and a measurable post-session review loop. The primary path remains lossless and authoritative; comparison is observational and fail-open.

Key decision: comparison never owns the delivery ledger. A slow, unavailable, or broken comparison provider cannot delay or revoke the production receiver path.

What this lets you answer after an interview

  • Which answer agents were active, and which provider was primary versus comparison?
  • How quickly did each provider begin responding, finish responding, and generate words?
  • Were answers broadly within the response-depth bands already defined by the PM interview policy?
  • Which question types tended to be too brief, on target, or too long?
  • How much queueing occurred, whether Manual Gather was used, and whether delivery/timeout issues occurred?

Analytics & post-session exports

Every completed answer can now carry response-shape and timing evidence from the answer lifecycle boundary. The combined export aggregates this by provider, role, and question type without adding a semantic-quality claim.

Per-answer measurements

  • Question type and target word band
  • Word count and band fit: too_brief, on_target, or too_long
  • First-token latency
  • Generation duration and total response duration
  • Observed output words per minute
  • Estimated speaking duration at the existing 129 WPM baseline
  • Provider and role identity

Aggregate review

  • Average and P95 first-token latency
  • Average and P95 generation and total response time
  • Average output WPM and speaking estimate
  • On-target / brief / long counts and percentages
  • Role activity, queue counts, answer timeouts, and delivery timing
  • Active providers, operator markers, unresolved items, and forwarding mode at export

Interpretation boundary: “depth” is a deterministic word-band proxy. A 140-word answer can still be weak and a 60-word answer can still be excellent. PMIA reports response shape and timing; it does not pretend to understand semantic interview quality from length alone.

Export files

The existing session export now triggers a combined analysis download in two forms: pmia-session-analysis-<session>.json for machine analysis and pmia-session-analysis-<session>.html for a readable review. The HTML includes overall KPIs, role activity, provider comparison, question-type target bands, P95 timing, WPM, speaking estimates, fit percentages, markers, queue mode and delivery state.

Manual Gather & expanded queue control

PMIA already had the correct underlying primitive: autoSubmit. 0.11.0 exposes it as an interview-time control instead of adding a second competing queue. When Manual Gather is on, authoritative finals continue to be admitted and protected, but provider submission is held until you decide the spoken fragments represent a complete question.

New shortcut: A toggles Manual Gather / Automatic Forwarding through the same authoritative command used by the button. There is no separate UI-only state to drift from the receiver runtime.

Comparison lane: production-strength test behavior

Window 3 is intentionally a strong test lane rather than a second production authority. It reuses the same provider adapters, answer orchestration, batch logic, sequence buffering, runtime ports, telemetry, logs and lifecycle titles as the primary answer window.

  • Session Studio can enable/disable comparison and choose ChatGPT or Claude independently.
  • The same persisted final is mirrored asynchronously after canonical routing is established.
  • Primary and comparison answer timings can be reviewed side by side in live analytics and exported reports.
  • Coordination settings that affect answer presentation can synchronize to both answer lanes.
  • Recovery controls that own canonical delivery remain primary-receiver-only.
  • If Window 3 cannot launch or become ready, PMIA degrades to primary-only instead of blocking the interview.
Safety property: the comparison lane can fail without turning a successful primary delivery into a failure.

Transport performance

The fastest path is still event-driven: when the provider exposes the authoritative rendered boundary, PMIA does not intentionally sleep before persistence or delivery. 0.11.0 focuses on reducing the fallback delays that matter when a provider signal is missing or late.

What “instant” can and cannot mean: PMIA can minimize its own handoff overhead, but it cannot make provider rendering, network latency, model first-token latency or model generation instantaneous. Those external times are now measured so tuning can separate transport delay from model delay.

Workspace, window chrome & help

The default full workspace now sizes itself from the current Windows work area rather than assuming one 1920×1032 desktop. Sender, primary receiver, optional comparison and Runtime Pilot share the available width. Managed provider app windows remove the normal Windows caption bar to reclaim vertical space while retaining resize/move behavior.

The help companion exposes the shortcut registry in the cockpit, so runtime controls are discoverable without a separate file. Current defaults include A Manual Gather, Space pause/resume, L catch-up, H health, R repair, E export, M mic, S scroll lock, N submit next, Ctrl+I interrupt latest, C copy latest, G health report, D diagnostics, Ctrl+K command palette and ? shortcut help.

How to operate 0.11.0

  1. Run runtime\Final_2_Window_Extension.ahk.
  2. In Session Studio, keep Edge Default/Profile 1 selected and run Preflight.
  3. Choose the Window 1 source provider and Window 2 primary answer provider.
  4. Enable Compare answers only when you want Window 3. Select the comparison provider; using the opposite provider is the normal test setup.
  5. Choose Three windows for sender + primary + optional comparison + cockpit in the adaptive work-area layout.
  6. During the interview, press A when several spoken fragments should be gathered before automatic submission. Press A again to restore automatic forwarding.
  7. Use the cockpit Help button or ? to see all runtime shortcuts.
  8. At the end, run Export. Keep the normal role exports and the new combined .json + .html session analysis for review.
Recommended comparison workflow: hold prompts, provider routes and answer-mode policy constant; compare first-token latency, total response time, word-band fit and operator markers over multiple question types. Treat one answer as anecdotal, not a provider ranking.

Limits, risks & the next tuning loop

Semantic quality remains a human/review-model job. The new “depth” signal is deliberately limited to target-band fit. It should be combined with operator markers and later qualitative review rather than promoted into a single opaque score.
  • External latency: model/network/provider rendering dominates some response times. First-token, generation and total-response metrics let us separate those from PMIA transport overhead.
  • Comparison capacity: a third active provider tab consumes browser/model resources. It is optional and fail-open so production use does not depend on it.
  • Question classification: current question types are deterministic rule-based categories aligned with canonical PMIA word bands. Ambiguous prompts may land in the simple default category.
  • Anonymous smoke limitation: isolated Edge verifies transport and UI but may not expose assistant text, so real-session analytics need real answer observations.
  • Best next optimization: collect several session exports, compare PMIA delivery timing against provider first-token timing, and tune only the stage that actually dominates.

The release does not delete provider cookies, login tokens, interview history or unrelated browser state. Comparison logs remain session-scoped under the same privacy model as existing PMIA session logs.

Release conclusion

PMIA 0.11.0 preserves the lossless primary interview path while adding a useful experiment/review loop around it. The key improvements are measurable rather than decorative: faster fallbacks, explicit manual gathering, provider comparison, answer timing and length-fit evidence, role-level export context, adaptive laptop layout and discoverable controls.

Release posture: production authority stays simple; test instrumentation is richer; failure of optional instrumentation cannot block the core interview.
