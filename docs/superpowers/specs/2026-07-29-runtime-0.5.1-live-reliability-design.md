# PMIA Runtime 0.5.1 Live Reliability Design

## Problem

The published 0.5.0 tree passes automated tests but fresh managed tabs crash during startup with `ReferenceError: sleep is not defined`. The title is applied before the crash, so the windows look managed while sender observation, registration, routing, and receiver delivery never become operational.

The attached extension-error screenshot also shows stale-tab `Extension context invalidated` errors after reload. Those are expected reload artifacts, but they are currently indistinguishable from a fresh startup failure in the user experience.

## Goal

Ship a live-tested 0.5.1 runtime that routes all four text provider combinations, exposes fatal startup failures on-page, and provides an active counterpart preflight instead of relying on window titles or registry state alone.

## Constraints

- Do not call private provider APIs.
- Do not retain raw audio or authentication material.
- Preserve the existing AHK launcher and legacy rollback files.
- Keep provisional previews disposable and final delivery durable.
- Do not close unrelated Edge windows.
- Use the canonical repository extension directory as the single source tree.
## Architecture

### 1. Startup dependency contract

`entry.js` must import every runtime dependency it passes to a controller. A source-level regression test will fail when `createReceiverController` receives an undeclared dependency. The immediate correction is to restore the exported `sleep` import used only for bounded stop-generation polling.

### 2. Fatal startup boundary

`content/main.js` will render a minimal emergency banner when the dynamic import fails. `entry.js` will also render the same banner when `startRuntime()` rejects after import. The banner includes the extension version and a short recovery action. It must not depend on the normal status overlay, because the failure may occur before normal runtime initialization completes.

### 3. Active counterpart preflight

`Ctrl+Shift+F11` will request an authorized service-worker preflight. The service worker will ping the opposite registered role with `PMIA_PREFLIGHT_PING`. The counterpart replies with role, provider, runtime version, and composer availability without modifying or submitting text.

The response distinguishes:

- both roles registered and counterpart responsive: `LINK OK`
- counterpart registered but content runtime unreachable: `RUNTIME UNREACHABLE`
- counterpart missing/stale: `WAITING SENDER` or `WAITING RECEIVER`
- a final is queued: `FINAL QUEUED`

### 4. Automatic link state

Registration responses will include session status. Each managed tab will render the current link state after successful registration, then preserve transient route statuses such as `FORWARDED`, `QUEUED`, `SENT`, and fatal errors.
## Error handling

- Reload-invalidated contexts show `RELOAD TAB` and do not masquerade as a healthy link.
- Fresh startup exceptions show `RUNTIME START FAILED` with the error class, not private transcript content.
- Preflight timeouts are bounded and never queue work.
- Preflight messages never touch the provider composer or generation state.
- Existing final delivery, sequence idempotency, and latest-only queue behavior remain unchanged.

## Verification

Automated:

- startup dependency regression test fails before the fix and passes after it
- fatal-banner tests cover import and startup rejection paths
- background preflight tests cover responsive, missing, stale, and unreachable counterpart states
- content preflight tests prove no composer mutation or submission
- all existing extension, manifest, AHK, validator, encoding, and secret checks remain green

Live:

- reload the unpacked extension through Edge
- clear old extension errors
- launch fresh managed pairs for ChatGPT→Claude, Claude→ChatGPT, ChatGPT→ChatGPT, and Claude→Claude
- run one uniquely marked text turn in each direction
- verify exact receiver submission and one answer per final turn
- run active preflight from both roles
- close only temporary verification windows

## Release

Version 0.5.1 is published only after the exact committed tree passes the full automated gate and the four-combination live text matrix. Voice behavior remains governed by the existing export-derived finalization rules and receives a focused smoke check without retaining audio.
