# PMIA 0.7 Reliability and Coherence Design

## Objective

Improve the Product Management mock-interview assistant without replacing its verified architecture. PMIA 0.7 must make live sessions safer, recovery more deterministic, exports more useful for mock review, and repository guidance consistent with the active Manifest V3 system.

## Binding constraints

- Work only in `C:\Users\Sundar\Documents\product-pm-interview-assistant-improvement`.
- Preserve the original checkout and all legacy, archive, and rollback files.
- Keep Microsoft Edge Stable, Manifest V3, AutoHotkey v2, two managed windows, and the current provider adapters.
- Do not add APIs, raw-audio capture, cookies, tokens, another browser extension, another window, or a backend.
- Do not persist Resume, Job Description, notes, prompts, answers, or session IDs to disk-backed extension storage.
- Do not run tests during implementation; run one consolidated verification gate after development is complete.

## Runtime state and privacy

Role-scoped logs move from `chrome.storage.local` to `chrome.storage.session`. The registry and logs therefore share the same browser-session-only storage boundary. On upgrade, the service worker removes legacy `pmia_log_*` keys from local storage without reading or exposing their values.

Ending a managed session removes its registry entry, pending final, and both role logs before the managed tabs finish closing. If both managed tabs disappear manually, the service worker removes the now-orphaned session and logs. Explicit export remains the only path that writes transcript material to user-visible files.

## Registration recovery

A fresh tab may encounter a role conflict when an earlier tab closed or lost its extension context but its registry heartbeat is still fresh. Before rejecting the new registration, the service worker probes the registered owner. It replaces the owner only when the tab is gone or its PMIA runtime does not respond with the expected role. A healthy duplicate remains rejected.

## Mock-review export

The receiver extracts only safe structured fields from the boot context: target company, target role, interview round, emphasis, answer mode, and missing Resume/JD flags. It never exports `Avoid mentioning`, Additional notes, Resume, or Job Description.

Each JSON and Markdown export gains a derived summary: whether the session armed, question count, answer count, average and maximum answer length, answer timeouts, delivery failures, and the safe session fields above. Raw role events remain available for detailed review. The schema advances to 2.1 while preserving the existing Markdown session and window headers used by the tracker resolver.

## Code boundaries

- `shared/session-log-store.js` owns ephemeral log reads, writes, clears, and legacy local-log cleanup.
- `shared/session-context.js` owns safe boot-context extraction and merging.
- `shared/session-log.js` owns event summarization and export rendering.
- `shared/session-registry.js` gains explicit session removal.
- `background.js` orchestrates registration probing and lifecycle cleanup but does not implement storage details.
- `content/entry.js` records safe session metadata when boot context is armed.

This keeps storage, parsing, rendering, and browser orchestration independently understandable.

## Documentation and release surfaces

Active README, install, status, handoff, runtime, File Map, and AI system-context documents must describe PMIA 0.7 and the current Edge Stable extension architecture. Historical 0.6.1 evidence and completed phase plans remain historical and are not rewritten as current work.

## Acceptance criteria

- No role transcript log is written to `chrome.storage.local`.
- Legacy local role logs are purged on runtime startup.
- End-session and final-tab closure remove registry, pending final, and both role logs.
- Dead/unresponsive prior registrations can be replaced; responsive duplicate roles remain blocked.
- Export contains safe metadata and review statistics, with no Resume, JD, avoid text, or notes.
- Existing tracker Markdown header compatibility remains intact.
- Active docs no longer present Edge Beta/Tampermonkey as the production runtime.
- One final consolidated test/validation command passes with no unrelated files modified.
