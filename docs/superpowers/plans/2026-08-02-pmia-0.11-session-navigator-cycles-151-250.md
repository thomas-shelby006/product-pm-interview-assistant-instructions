## Named new implementations from the latest requirements

1. **Adaptive Turn Coordination** — the umbrella state machine coordinating finalized source turns, receiver generation, hold/release and interruption carryover.
2. **Forwarding Hold** — persisted Pause/Resume control that blocks receiver submission but never blocks durable admission.
3. **Paused Combined Draft** — protected Window 2 composer content containing every held final in exact sequence.
4. **Auto-Release Submission** — verified automatic submission on Resume when the receiver composer is ready and conflict-free.
5. **Source Interruption Correlator** — distinguishes a genuine source-answer interruption followed by a continuation from normal source completion.
6. **Interrupted Answer Carryover** — stops the matching receiver answer once, marks it as not landed and carries its source segments into the next combined batch.
7. **Continuation Chain** — supports two or more sequential question segments without losing or reordering any segment.
8. **Finalized-Turn Admission** — admits only authoritative finalized DOM turns; provisional transcript growth remains preview-only.
9. **Turn Latency Budget** — explicit p50/p95 budgets for admission, composer projection, stop action and release submission.
10. **Twenty-Turn Throughput Proof** — deterministic zero-loss acceptance for at least 20 finalized turns per minute.

### Stage 1 — Adaptive Turn Coordination design and contracts

**Architecture decision:** extend the existing DeliveryLedger, BatchPlanner, receiver batch runtime, answer lifecycle and Runtime Pilot state. Do not introduce another queue, another persistence store or a second submission owner.

**State model:**

- `forwardingHold.active`: operator-controlled persisted hold.
- `forwardingHold.activatedAt`, `reason`, `heldMemberIds`, `releaseMode`.
- `interruptionChain.id`, `memberIds`, `cancelledBatchId`, `sourceEvidence`, `receiverStopState`, `createdAt`.
- `combinedDraft.memberIds`, `fingerprint`, `prompt`, `projectedAt`, `manualConflictState`.

**Prompt contract for held or carried-over segments:**

> Forwarding was paused or the previous answer was interrupted and should be treated as not delivered. Use every question segment below as one combined context. Preserve relevant earlier context, focus primarily on the latest question, and answer the combined request. Do not assume the previous answer reached the user.

Segments are numbered in exact source order. The prompt is frozen with an exact member fingerprint before submission.

**Safety rules:**

- Durable admission continues while held.
- Pause never deletes, archives, supersedes or proves a final.
- Resume cannot auto-submit while a manual composer conflict exists.
- Receiver generation is stopped only when source interruption evidence is correlated to the active receiver batch.
- Ordinary later finals continue accumulating and never interrupt generation.
- A stop action is idempotent and bound to one receiver generation/batch token.
- A failed stop preserves the complete chain and presents one explicit recovery action.
- Reload or service-worker restart restores hold, chain and draft identity without storing answer text.
