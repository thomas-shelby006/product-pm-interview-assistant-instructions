## Execution amendment — system architecture and lifecycle

The latest approved scope adds these hard requirements to Cycles 151–250:

- one project runtime instance; a second launch activates the existing Studio instead of replacing an active session;
- a normalized browser runtime configuration with Edge as the default, Chrome-compatible executable/profile support, reviewed low-latency flags and browser-specific internal URLs;
- one managed-process/window ownership journal so relaunch and shutdown close only PMIA-created windows/processes for the selected session;
- no automatic foreground activation during launch, repair or cleanup; focus changes require an explicit operator action;
- one phase-oriented Pilot workflow: pre-launch, launch, live mock, export, review and graceful shutdown;
- one post-interview transaction covering role export, export verification, Review Studio handoff, safe end preparation, exact managed-window cleanup and AHK exit;
- complete Pilot access to launch health, browser/profile state, export/review status, managed-window ownership and shutdown actions;
- route verification for ChatGPT→ChatGPT, ChatGPT→Claude, Claude→ChatGPT and Claude→Claude without repeating evidence already proven on the same unchanged owner;
- removal of dead production modules and source-shape-only tests; new tests must exercise real behavior and fail when the production owner regresses;
- the standalone HTML report remains explicitly out of scope for this run.

Cycle mapping: Navigator and phase workflow are delivered in 151–200; command/snapshot/transport/provider/state/performance hardening remains 201–250. Single-instance, browser abstraction, managed ownership, export/review/shutdown and code/test cleanup are mandatory cross-cutting acceptance work inside Blocks 236–250.
